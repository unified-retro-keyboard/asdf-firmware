* Keymap architecture
** Keymap definition modules are in src/Keymaps
** Each keymap is described by one immutable descriptor
*** const asdf_keymap_t FLASH mapname_keymap - keymap descriptor (asdf_keymaps.h)
**** a keycode map for each modifier state (plain, shift, caps, ctrl)
***** The keycode maps are in flash (ROM)
***** all maps share the descriptor's row and column count
**** the delay between system message characters
**** hook bindings: table of { hook id, function }
**** virtual output assignments: table of asdf_virtual_initializer_t
***** virtual device to physical device mapping
***** associated virtual device function on activate
***** initial state
**** flags: start with CAPSLOCK on, start with negative strobe
**** optional platform, for keymaps that need special scanning or output
** The descriptor and its tables are stored in flash
** Keymap registry
*** keymap_list.cmake lists each keymap as <name:number>
*** The build generates a flash table of descriptor pointers by number
    (asdf_keymap_setup.c.in); asdf_keymap_descriptor(number) looks one up.

** Selecting a keymap (asdf_keymaps_switch)
*** reset the architecture and all runtime state (maps, virtual outputs,
    modifiers, repeat, hooks, platform)
*** apply the descriptor, in field order: maps, print delay, hooks, virtual
    outputs, flags, platform
*** re-apply the configuration actions of held switches (keymap select,
    strobe polarity, autorepeat select); other held keys are not re-activated
*** drive every output to its initial value (asdf_virtual_sync)


* DIP SWITCHES
  Note that the DIP switches are keys in the key matrix, which is initialized to
  the all unpressed state at startup. Since the keymap is initialized to 0, the
  keymap is consistent with the presumed initial state of the DIP switches. If
  the DIP switches are not set to Keymap 0, then their position will be detected
  as keypresses, and the correct keymap will be set.
